# DoH request lifetime

After initial endpoint bootstrap, `queryTimeout` covers request-slot waiting, HTTP headers and the complete DNS response body. The first decoded DNS response retains its RCODE, including SERVFAIL and NXDOMAIN, and cancels losing HTTP attempts. This does not cancel the caller's wider resolver graph or change DNS64 synthesis rules.

When known endpoints all fail, hostname refresh runs outside the failed query's critical path. Refresh is coalesced to one worker per resolver instance, with at least one second between starts. Failed or empty refresh results retain the previous endpoint snapshot. A query with an empty snapshot can await the shared refresh and retry within its remaining request budget. Initial bootstrap retains the configured resolver path. That resolver interface has no cancellation: one blocked refresh can remain active until its resolver returns, but it cannot spawn additional refresh workers while blocked.

For a bounded operator diagnostic, `SECDNS_RESOLVER_TRACE_SECONDS` accepts 1–180 seconds from process initialization. It defaults off. Completed phase spans are written to stderr without names, addresses, URLs, headers, answers or error strings. Detail is capped at32768 events through a nonblocking512-entry queue. A summary reports drops/write errors, active spans and per-phase completed counts/max durations. Missing spans or an exhausted cap are not evidence of unfinished work. DNS IDs are only correlation hints, not unique request lineage. Remove the service environment after starting the capture; do not restart merely to extend it.
